1. Status atual

  • Produto: Vetorizador Inteligente (v1.4.0; revisão Windows 1.4.0.2)
  • Plataforma: Windows 10/11 (x64)
  • Status geral: Pacote de teste instalado, WACK geral PASS e inferência local verificada com SAC enforced; certificação de distribuição pendente.

O reteste de 07/11 concluiu lint, build, dez testes Node e quatro casos de preflight. O pacote foi instalado por atualização da mesma identidade, sem desinstalação. Os 428 componentes nativos foram verificados com assinatura local e o MSIX recebeu status Valid. Não houve nova submissão ou certificação Microsoft Store.

Duas pendências opcionais do WACK

  • Uso de arquivo morto: três arquivos compactados de dados (fusos horários dateutil, grafos NetworkX e vocabulário MMSeg), preservados porque têm consumidores produtivos.
  • Executáveis bloqueados: 67 mensagens de referências a APIs de início de processos, como CreateProcessW, nos componentes distribuídos. Referência estática não significa bloqueio observado durante os testes nem reprovação do teste obrigatório de APIs compatíveis.

Ambas estão marcadas OPTIONAL=TRUE no relatório. O resultado geral PASS não significa 24/24 aprovados e não substitui a decisão de certificação da Store.

6. Build e empacotamento

npm run dist:win        # Instalador NSIS (distribuição técnica local)
npm run dist:win:store  # MSIX sem assinatura local para submissão
npm run dist:win:store:test  # MSIX assinado para teste local
  • Instalador NSIS por usuário, sem exigir privilégios de administrador.
  • Pacote de teste assinado localmente, verificado por Get-AuthenticodeSignature. O pacote de submissão recebe assinatura Microsoft após certificação, não o certificado de desenvolvimento.
  • Para reconstruir o manifesto atual em PowerShell, definir $env:VETORIZADOR_APPX_REVISION = '2' antes de npm run dist:win:store:audit -- -Test. A versão de engenharia permanece 1.4.0.

7. Segurança operacional para homologação

  • O aplicativo opera com persistência local-first e não envia arquivos operacionais ao fabricante.
  • O shell desktop publicado não depende de bibliotecas remotas para sua operação principal em runtime.
  • A exceção wasm-unsafe-eval existe apenas para a instanciação do módulo Rust/WebAssembly local.
  • O escopo de risco assumido exclui malware já instalado com o mesmo privilégio do usuário.
